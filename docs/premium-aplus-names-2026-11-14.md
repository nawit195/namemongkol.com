# ชีต A+ และรายละเอียดชื่อพรีเมียม

## การเปลี่ยนแปลง

ใช้เฉพาะชีต `A+` ของ `รายชื่อคัดกรอง (1).xlsx` จำนวน 531 ชื่อ ไม่ซ้ำกัน ข้อมูลที่สกัดอยู่ใน `scripts/data/premium-aplus-2026-11-14.json` พร้อมแถว ที่มา SHA-256 และรายการข้ามชื่ออังกฤษ `ขันธ์` ซึ่งเป็นภาษาไทย ไม่เดาคำถอดเสียง จึงมีชื่ออังกฤษพร้อมใช้ 530 รายการ

Migration `supabase/migrations/20261114061236_premium_name_details.sql` เพิ่ม pronunciation, meaning, english_name และสถานะตรวจคำอ่าน/ความหมายใน premium_names ข้อมูลใหม่เป็น pending ไม่เปลี่ยน RLS หรือ grants และไม่เขียนข้อมูลไป auspicious_names

API `/api/public/premium-names` รวมรายละเอียดสาธารณะเดิมกับรายละเอียดพรีเมียม โดยรักษาค่าที่มีอยู่แล้ว ใช้ข้อมูลพรีเมียมเฉพาะช่องที่ขาด บล็อกสถานะ rejected และตัดชื่อ hidden ตามแหล่งเดิม เพิ่ม englishName แบบ optional รองรับฐานก่อน migration และอ่านครบทุกหน้าครั้งละ 1,000 แถว

ชื่ออังกฤษส่งต่อผ่านชุดรายชื่อร่วมไปยังการ์ด `/premium-search` ตามสิทธิ์ปลดล็อกเดิม และผลลัพธ์ `/premium-analysis` พร้อมคำอ่าน ความหมาย และป้ายรอตรวจ ประวัติเก่าไม่มีฟิลด์ใหม่ยังเปิดได้ ไม่แก้ snapshot เดิม ไม่เปลี่ยนสูตร คะแนน เกรด วันเกิด ราคา หรือการหักเครดิต และไม่เพิ่มชุดนี้ใน fallback ฝั่ง client

จำนวนรายชื่อใน header/ตารางเปรียบเทียบและ JSON-LD ใช้ชุดเผยแพร่จริง หากอ่านจำนวนไม่ได้ให้ใช้ข้อความไม่ระบุตัวเลข แทนการนำจำนวน fallback มาโฆษณาเป็นจำนวนฐานจริง

## การนำเข้า

`scripts/extract-premium-aplus-names.py` อ่าน Excel ด้วย bundled Python/openpyxl โดยไม่แก้ต้นฉบับ

`node scripts/import-premium-aplus.mjs` เป็น dry run เท่านั้น อ่านครบทุกหน้า สำรอง before-values และสร้าง SQL ใน `scratch/premium-aplus-import/` ซึ่งถูก gitignore ใช้ตัววางแผนและตัวสร้าง SQL ร่วมกับ importer A-B โดยจำกัดชื่อตารางที่อนุญาตและไม่ใส่ gender ใน premium_names

ก่อนนำเข้าจริงต้องติดตั้ง migration แล้วทำ dry run ใหม่เพื่อให้ snapshot ตรง schema ล่าสุด SQL ใช้ lock_timeout 5 วินาที ล็อกตารางโดยยังอ่านได้ ตรวจ snapshot และเขียนใน transaction เดียว หากข้อมูลเปลี่ยนให้ยกเลิกทั้งชุดและทำ dry run ใหม่ หลังรัน SQL ใช้ `node scripts/import-premium-aplus.mjs --verify` ตรวจค่าทุกแถวที่เปลี่ยนและการรันซ้ำต้องไม่มีงานเหลือ

Dry run ก่อนติดตั้งพบชื่อใหม่ 178 ชื่อ ชื่อเดิม 353 ชื่อ เติมคำอ่าน/ความหมายใน premium_names 531 รายการต่อช่อง และชื่ออังกฤษ 530 รายการ รายละเอียดเดิมในฐานสาธารณะยังมีลำดับก่อนข้อมูลใหม่ผ่าน API

## การตรวจรับ

- PGlite รัน migration และ SQL นำเข้า 531 ชื่อจริงบนฐานจำลอง ผ่าน bigint IDs, pending, ชื่ออังกฤษ 530 รายการ, ขันธ์เว้นว่าง, รันซ้ำ, snapshot เปลี่ยนแล้ว rollback และตรวจไม่เขียนตารางสาธารณะ
- Unit/integration tests ครอบคลุมการอ่าน 1,205 รายชื่อบน schema ปัจจุบัน/ก่อน migration, ค่าร่วมที่อนุมัติ/ปฏิเสธ/ซ่อน, คะแนนและเกรดก่อน–หลังเติมรายละเอียดเท่ากัน, การแสดงผลทั้งสองหน้า และประวัติเก่า
- UI fixture ใช้ component ผลลัพธ์จริงและ CSS ของ build โดยแยก auth/เครดิตออก ตรวจ 320px และ 390px ไม่ล้นแนวนอน (scrollWidth 305/375px) และตรวจภาพ desktop 1280px ชื่ออังกฤษ ข้อมูลขาด และป้าย pending อ่านได้ ไม่ใช้เครดิตจริง
- รอบ tests ขนานเริ่มแรกมี timeout สองรายการเดิมของโครงการ เมื่อจำกัด workers ผ่านครบ 67 files / 334 tests รวมกรณีจำนวน fallback และตรวจซ้ำเฉพาะส่วนหลังปรับชนิดข้อมูลอีก 16 tests ผ่าน
- Full lint ไม่มี errors มี warnings เดิม 46 รายการ
- TypeScript แยกผ่าน และ targeted lint ของไฟล์ที่แก้รอบสุดท้ายไม่มี warnings/errors
- ตัวสร้าง SQL เลือก dollar-quote delimiter ที่ไม่ปรากฏในข้อมูล ทดสอบกับข้อความ `$import_guard$` / `$check$` แล้วเก็บเป็นข้อมูลได้ ไม่กลายเป็นคำสั่ง SQL
- Production build ผ่าน 220 static pages
- ล้างเฉพาะไฟล์ build cache local ที่มี tag premium-names ภายใน .next (53 entries) แล้วเริ่ม preview process ใหม่ ไม่เปลี่ยน cache/secret บน production
- จำลอง TTL หมดอายุเฉพาะไฟล์ HTML cache local ของ premium-search โดยตั้ง mtime เกิน 600 วินาที ตรวจ STALE แล้วให้ ISR สร้างหน้าใหม่จากข้อมูลจริง ไม่แก้ source code หรือเนื้อหา HTML ด้วยมือ
- หลัง ISR ตรวจ premium-search ได้ HIT และจำนวน 4,443 ใน HTML/JSON-LD จริง ทั้ง premium-search และ premium-analysis ตอบ 200 และมี H1

## ขอบเขตการเผยแพร่

งานนี้ไม่รวม Commit/Push หรือ deploy โค้ด production ไม่ส่ง secret ไปภายนอกเพื่อ invalidate cache ใช้ TTL 600 วินาทีและตรวจผลจาก API แทน หน้าเว็บจริงจะแสดงรายละเอียดใหม่เมื่อเผยแพร่โค้ดนี้แล้ว
