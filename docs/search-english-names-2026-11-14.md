# รายชื่อ A-B และชื่อภาษาอังกฤษ

## ข้อมูลและผลติดตั้งจริง

ใช้เฉพาะชีต `A-B` ของ `รายชื่อคัดกรอง (1).xlsx` จำนวน 1,003 ชื่อ ไม่รวมชีต A+ และไม่ใช้คะแนน/เกรด/วันจาก Excel แทนสูตรเว็บไซต์

ติดตั้งคอลัมน์ nullable `auspicious_names.english_name` บน Supabase โครงการ `ykujxndttruqzhmufdzr` และนำเข้าข้อมูลจริงเมื่อ 14 พฤศจิกายน 2569:

| รายการ | จำนวน |
| --- | ---: |
| ชื่อใหม่ (neutral) | 460 |
| ชื่อที่มีอยู่แล้ว | 543 |
| ชื่อเดิมที่เติมชื่ออังกฤษ | 542 |
| คำอ่าน/ความหมายที่เพิ่มสำหรับชื่อใหม่ | อย่างละ 460 |
| ชื่อภาษาอังกฤษทั้งหมดในชุดนำเข้า | 1,002 |
| ช่องข้อมูลที่ต่างจากไฟล์และรักษาของเดิมไว้ | 638 |
| ฐานรายชื่อหลังนำเข้า | 7,808 |
| การเปลี่ยนแปลงที่เหลือเมื่อจำลองนำเข้าซ้ำ | 0 |

`นาวิน` ไม่มีข้อมูลคำอ่าน/ความหมาย/อังกฤษในไฟล์ จึงไม่เติมจากการเดา ส่วน `นิรภัฏ` แก้อักขระการันต์ที่ปนหน้า `์NIRAPHAT` เป็น `NIRAPHAT` โดยเก็บบันทึก correction และ SHA-256 ของต้นฉบับในชุดข้อมูลที่สกัดแล้ว

ค่าคำอ่าน ความหมาย เพศ วันที่สร้าง และสถานะเดิมยังคงอยู่ การเติมข้อมูลใหม่คงสถานะ pending ไม่ได้อ้างว่าผ่านการตรวจภาษา มีเงื่อนไขไม่เติมทับ approved/rejected/draft ที่มีข้อมูล และไม่เปิดเผยชื่อ hidden บน schema ที่รองรับสถานะดังกล่าว ฐานจริงปัจจุบันยังไม่มี pronunciation_status/publication_status จึงรองรับผ่าน schema compatibility เดิมโดยไม่ติดตั้ง migration งานอื่นที่ค้างอยู่

## โค้ดและขั้นตอนนำเข้า

- Migration: `supabase/migrations/20261114044636_public_names_english.sql` ไม่เปลี่ยน RLS หรือสิทธิ์เดิม
- `scripts/extract-filtered-names.py` อ่าน Excel ด้วย bundled Python/openpyxl โดยไม่แก้ต้นฉบับ ผลลัพธ์ `scripts/data/filtered-names-ab-2026-11-14.json` เก็บที่มา ชีต แถว และการแก้ไข ไม่ถูกนำเข้า client bundle
- `node scripts/import-filtered-names.mjs` เป็น dry run เท่านั้น อ่านฐานทุกหน้าครั้งละ 1,000 แถว สำรอง before-values และสร้าง SQL ใน `scratch/filtered-names-import/` ซึ่งถูก gitignore
- SQL นำเข้าล็อกตารางแบบไม่บล็อกการอ่าน แล้วตรวจ snapshot และเขียนใน transaction เดียว หากข้อมูลเปลี่ยนต้องยกเลิกและเตรียมใหม่ ไม่เรียก importer เพื่อเขียนฐานอัตโนมัติ
- หลังรัน SQL ใช้ `node scripts/import-filtered-names.mjs --verify` ตรวจทุกฟิลด์ของแถวที่เปลี่ยนกับ snapshot รวม patch ตรวจข้อมูลเดิมและตรวจว่ารันซ้ำไม่มีงานเหลือ ผ่านแล้วบนฐานจริง
- เก็บ snapshot ก่อนเปลี่ยนไว้ในเครื่อง ไม่ Commit ไฟล์ backup/SQL ที่สร้างตามข้อมูลฐาน

## การแสดงผลและ compatibility

ผลข้อมูลเดิมเพิ่ม `englishName?: string` ทั้ง SSR, JSON API, static initial previews และ CSV ชื่ออังกฤษอยู่หลังชื่อไทยบนเดสก์ท็อป ส่วนมือถืออยู่ใต้ชื่อไทยและในรายละเอียด พร้อมคำอธิบายว่าเป็นตัวเลือกการสะกดตามต้นทาง ไม่ยืนยันสำหรับเอกสารราชการ

ชื่อที่ไม่มีข้อมูลแสดง `—` และข้อความ “ยังไม่มีข้อมูล” ในรายละเอียด CSV เว้นช่องว่าง ใช้ BOM/escape/ป้องกันสูตรตามเดิม ไม่เปลี่ยนการกรอง เกรด สิทธิ์โหลดเพิ่ม หรือเครดิต

ทุกโหมดอ่านฐานรองรับ english_name; หากยังไม่มีคอลัมน์ให้ถอยมาอ่านข้อมูลเดิมโดยไม่ทำให้รายชื่อหาย เพิ่มโหมดอ่าน meaning_status บนฐาน legacy เพื่อไม่ทำสถานะ pending สูญหายระหว่าง fallback เปลี่ยนเวอร์ชัน cache ข้อมูลและ client เพื่อไม่ใช้ payload รุ่นเดิมหลัง deploy

- Lint: 0 errors, 46 warnings เดิม; production build ผ่าน 220 static pages

## Cache และการเผยแพร่

ยังไม่ Commit/Push หรือ deploy โค้ด production ชื่ออังกฤษจะแสดงบนเว็บจริงหลังเผยแพร่โค้ดนี้

ระบบ automatic approval ปฏิเสธคำสั่ง external cache revalidation เนื่องจากคำสั่งมีการส่ง secret จาก `.env.local` ไปยัง `www.namemongkol.com` จึงไม่ดำเนินการหรือพยายามส่ง secret ด้วยวิธีอื่น ใช้ cache TTL เดิมแทน พบว่าเครื่องไม่ได้ตั้ง REVALIDATE_SECRET สำหรับ local endpoint ด้วย จึงไม่ถือว่า flush cache สำเร็จ API เว็บจริงยังเป็นโค้ดเดิมและยังไม่ส่ง englishName เป็นพฤติกรรมที่คาดไว้ก่อน deploy
