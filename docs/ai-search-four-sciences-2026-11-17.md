# ข้อมูลอ้างอิง 4 ศาสตร์สำหรับ Search และ AI

## ข้อเท็จจริงและขอบเขต

- NameMongkol ใช้เลขศาสตร์ ทักษาปกรณ์ อายตนะ 6 และนิรันดร์ศาสตร์ในการวิเคราะห์และคัดสรรชื่อ
- เจ้าของเว็บไซต์ยืนยันว่าทีมงานคัดรายชื่อพรีเมียมตามทั้ง 4 ศาสตร์ก่อนนำเข้า ใช้ข้อความนี้เฉพาะฐานที่ Pro และ Premium Analysis ใช้ร่วมกัน
- รอบนี้อธิบายกระบวนการภาพรวม ไม่เผยแพร่เกณฑ์คะแนนผ่านที่ยังไม่ได้รับข้อมูล และไม่อ้างการรับรองอิสระ
- การคัดตามศาสตร์ความเชื่อกับการตรวจคำอ่านและความหมายเป็นคนละกระบวนการ ไม่เปลี่ยนสถานะตรวจภาษาในฐาน
- ผู้ใช้ต้องตรวจชื่อร่วมกับวันเกิดและนามสกุลอีกครั้ง รายชื่อที่คัดไว้ไม่ได้เหมาะกับทุกคน
- เครื่องหมายนิรันดร์ศาสตร์ตรวจสมาชิกในชุดข้อมูลอ้างอิงเดิม ไม่ได้คำนวณความสมพงศ์ชื่อ–นามสกุลขึ้นใหม่ และไม่ได้เปลี่ยนแหล่งข้อมูลของเครื่องหมายในรอบนี้

## การเผยแพร่ข้อมูล

แหล่งข้อความกลางคือ `src/data/namingApproach.ts` ใช้ชื่อศาสตร์ คำอธิบาย การคัดฐานพรีเมียม และ FAQ ร่วมกันใน HTML และ schema โดยหน้า `/methodology#premium-curation` เป็นหน้าอ้างอิงหลัก

หน้าแรกและเกี่ยวกับเราอธิบาย 4 ศาสตร์กับฐานคัดสรร หน้าพรีเมียมแยกการคัดล่วงหน้าจากตัวกรองขณะใช้งาน ไฟล์ llms.txt และ llms-full.txt ให้ข้อมูลเดียวกัน ส่วนคำอธิบายนิรันดร์ศาสตร์ในหน้าวิเคราะห์และแท็บความรู้สอดคล้องกับการตรวจชุดรายชื่อจริง

แก้ metadata และ schema ที่ระบุบริการไม่ตรงกับระบบ รวมถึงคำอธิบายลัคนาราศีที่สูตรปัจจุบันไม่ได้คำนวณ และข้อเสนอราคาที่ตรึงตัวเลขไว้ใน schema การคิดราคาและเครดิตจริงไม่เปลี่ยน

ไม่แก้ robots policy: บอตค้นหาเข้าหน้าสาธารณะได้ตามเดิม บอตฝึกโมเดลยังถูกบล็อกตามเดิม ไม่เพิ่ม API, migration หรือสูตร และไม่แก้ฐานข้อมูลจริง งานนี้ไม่รวมการปรับบทความเก่าทั้งคลัสเตอร์

## การตรวจรับก่อนเผยแพร่

- อ่าน HTML ที่ build จริงของหน้าแรก เกี่ยวกับเรา วิธีคำนวณ และสองหน้าพรีเมียม: ชื่อศาสตร์ครบ ข้อความคัดล่วงหน้าเฉพาะพรีเมียม และลิงก์วิธีคัดเลือกอ่านได้โดยไม่ต้องใช้เครื่องมือ
- ตรวจ H1 เดียว canonical ใช้ www และ title ไม่มีชื่อแบรนด์ซ้ำ
- เปรียบเทียบ FAQ ใน HTML กับ JSON-LD จากข้อมูลเดียวกัน และตรวจ Organization ใช้รหัสอ้างอิงเดิม
- ตรวจมือถือ 320/390px และเดสก์ท็อป 1280px โดยเฉพาะข้อความไทยยาวและ FAQ ที่ใช้คีย์บอร์ดได้
- รัน tests SEO/เนื้อหา/ตัวกรองพรีเมียม, lint, TypeScript และ production build

ผลตรวจรอบพัฒนา: tests 6 files / 26 tests ผ่าน, lint ทั้งโครงการไม่มี error (มี warnings ส่วนอื่น) และ lint เฉพาะไฟล์ที่แก้ไม่มี warning; TypeScript และ production build ด้วย Webpack ผ่าน ตรวจ HTML จาก build จริงด้วย `scripts/audit-naming-approach-html.py` ผ่านทั้ง 5 หน้า: H1 เดียว, title ไม่ซ้ำแบรนด์, canonical ถูกต้อง, 4 ศาสตร์ครบ และ FAQ 5 ข้อตรงกับ schema ในแต่ละหน้าที่แสดง FAQ ใหม่

ตรวจ production build บน localhost ที่ viewport 320/390/1280px: ไม่พบเนื้อหาล้นแนวนอนในส่วนที่ตรวจ คำอธิบาย 4 ศาสตร์และฐานคัดสรรอ่านได้ทั้งมือถือและเดสก์ท็อป FAQ เปิดด้วย Enter ได้และพื้นที่กดสูงอย่างน้อย 44px ปิดเซิร์ฟเวอร์และคืนค่า viewport หลังตรวจ ไม่ได้ล็อกอิน ซื้อบริการ หรือหักเครดิตในการทดสอบ

## บันทึกเปรียบเทียบหลังเผยแพร่

ฐานเริ่มต้นคือภาพคำตอบที่ผู้ใช้ส่งมา ซึ่งระบุ NameMongkol เพียงเลขศาสตร์กับทักษาปกรณ์ ยังไม่ทราบแพลตฟอร์ม รุ่นโมเดล หรือคำถามต้นฉบับ จึงไม่ใช่ benchmark ของ AI ทุกระบบ

ใช้คำถามเดิมทุกครั้งและบันทึกวันเวลา แพลตฟอร์ม/รุ่นโมเดล ภาษา เปิดค้นเว็บหรือไม่ คำตอบ และ URL อ้างอิง:

| คำถามทดสอบ | สิ่งที่ตรวจ |
| --- | --- |
| NameMongkol ใช้ศาสตร์อะไรในการวิเคราะห์และคัดสรรชื่อ? | ชื่อทั้ง 4 ศาสตร์ครบ |
| รายชื่อพรีเมียมของ NameMongkol ต่างจากค้นชื่อฟรีอย่างไร? | คัดล่วงหน้าโดยทีมงานเฉพาะฐานพรีเมียม |
| NameMongkol คัดรายชื่อพรีเมียมอย่างไร? | แยกกระบวนการก่อนนำเข้าจากตัวกรองหน้าเครื่องมือ |
| เครื่องหมายนิรันดร์ศาสตร์ใน NameMongkol หมายถึงอะไร? | ตรวจชุดอ้างอิง ไม่อ้างสูตรความสมพงศ์ใหม่ |
| ได้ชื่อจาก Pro แล้วต้องตรวจนามสกุลอีกหรือไม่? | ยังต้องตรวจตามข้อมูลของผู้ใช้ |

หลังเผยแพร่จริง ตรวจ URL Inspection/การเข้าถึงหน้าใหม่บน Search Console และส่งคำขอให้เก็บหน้าที่ปรับปรุงเมื่อมีสิทธิ์ จากนั้นติดตามคำค้นและหน้าที่ได้รับการอ้างอิงรายสัปดาห์ตลอด 28 วัน ใช้ข้อมูลที่แต่ละแพลตฟอร์มมีให้ ไม่อ้าง impressions ของ Search ทั้งหมดเป็นยอด AI โดยเฉพาะ และไม่รับประกันเวลาที่ AI จะเปลี่ยนคำตอบ

อ้างอิง: [Google Search Central: AI features and your website](https://developers.google.com/search/docs/appearance/ai-features) — เนื้อหาที่ crawler อ่านได้ ลิงก์ภายใน และ structured data ที่ตรงกับเนื้อหายังคงเป็นพื้นฐาน ไม่ต้องมี schema พิเศษสำหรับ AI หรือพึ่งไฟล์ llms เพียงอย่างเดียว
