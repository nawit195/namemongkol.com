# เก็บชื่อหลังเข้าสู่ระบบ และเครดิตการเปรียบเทียบ

## พฤติกรรม

- ต้องเข้าสู่ระบบด้วยบัญชีจริงก่อนเก็บ/ลบชื่อหรือเปิดรายการชื่อที่ชอบ ไม่รับ anonymous sign-in
- รายการยังบันทึกในอุปกรณ์ แยก key ตามบัญชี สูงสุด 50 รายการ ไม่ได้เพิ่มการ sync ข้ามอุปกรณ์
- กดหัวใจขณะยังไม่เข้าสู่ระบบจะจำชื่อที่เลือกใน sessionStorage และกลับมาบันทึกหลัง Login สำเร็จ ไม่ใส่ชื่อใน URL
- การสลับบัญชี/ออกจากระบบล้างรายการที่แสดงและตัวเลือกเปรียบเทียบของบัญชีเดิม
- เปรียบเทียบ 2–3 ชื่อฟรี ไม่ต้องเข้าสู่ระบบ
- เปรียบเทียบ 4 หรือ 5 ชื่อใช้ **10 เครดิตต่อชุด** เท่ากัน ไม่ใช่คิดเพิ่มตามจำนวนชื่อที่เกิน
- ตรวจเครดิตฝั่งเซิร์ฟเวอร์ก่อนแสดงหน้าต่างยืนยัน โดยแสดงจำนวนชื่อ ยอดก่อน–หลัง และปุ่มยืนยัน ไม่หักเมื่อกดดูราคา หรือกลับจาก Login
- ชุดเดิมต่อบัญชีเปิดซ้ำฟรี แม้สลับลำดับชื่อหรือเปลี่ยนตัวพิมพ์อังกฤษ จัดตารางกลับตามลำดับที่กรอกล่าสุด เปลี่ยนชื่อ นามสกุล หรือวันเกิดเป็นชุดใหม่
- รายงานสรุป/PDF/CSV เดิมเป็นบริการแยก 5 เครดิต หากซื้อทั้งการเปรียบเทียบ 4–5 ชื่อและรายงานใหม่ รวมเป็น 15 เครดิต มีการยืนยันแยกกัน
- รายงานที่ซื้อไว้ก่อนหน้ายังเปิดได้โดยไม่เรียกเก็บย้อนหลัง

## ฝั่งเซิร์ฟเวอร์และฐานข้อมูล

API ใหม่ `POST /api/compare-names/compare` รองรับ `?preview=1` ตรวจราคาโดยไม่หักเครดิต ใช้ session จริง ไม่รับ user ID ราคา หรือคะแนนจากเบราว์เซอร์มาตัดสิน และใช้ `Cache-Control: private, no-store`

Migration: `supabase/migrations/20261110045223_comparison_access_credits.sql`

ติดตั้ง migration นี้ใน Supabase ก่อนเปิดใช้บริการหักเครดิต โดยใช้กระบวนการ migration ของโครงการ หรือ SQL Editor หลังตรวจไฟล์ ต้องมีตาราง `user_profiles`, `credit_transactions` และระบบรายงานเดิมอยู่แล้ว

ตาราง `comparison_access` เปิด RLS ให้อ่านได้เฉพาะเจ้าของ ไม่อนุญาตให้ browser เขียน และ RPC `unlock_comparison_access` เรียกได้เฉพาะ service_role ล็อกแถวเครดิต ตรวจสิทธิ์ชุดเดิมซ้ำ หัก welcome credits ที่ยังไม่หมดอายุก่อนเครดิตซื้อ และบันทึกสิทธิ์/รายการใช้เครดิตใน transaction เดียว

API รายงานเดิมตรวจสิทธิ์การเปรียบเทียบ 4–5 ชื่อก่อนซื้อรายงานใหม่ ป้องกันการใช้รายงาน 5 เครดิตข้ามค่าบริการ 10 เครดิต

หากยังไม่ติดตั้ง migration หรือระบบตรวจเครดิตขัดข้อง จะไม่เปิดผล 4–5 ชื่อและไม่ใช้การคำนวณฟรีเป็น fallback ส่วน 2–3 ชื่อยังทำงานตามปกติ

## การตรวจสอบ

- Full suite: 59 ไฟล์ / 308 tests ผ่าน (`vitest run --maxWorkers=2`)
- Production build ผ่าน สร้าง static pages 219 หน้า; lint ไม่มี errors มี warnings เดิม 46 รายการ
- PostgreSQL จำลองผ่าน: เครดิต 0/9/10, welcome credits ก่อนเครดิตซื้อและการหมดอายุ, เปิดซ้ำ, คำขอซ้ำ/ต่างชุดที่เข้า queue, การใช้ยอดร่วมกับรายงาน, transaction rollback, RLS และ service-only RPC
- PGlite ทดสอบด้วย connection เดียวที่จัด queue; ยังไม่ได้ทดสอบ load หลาย PostgreSQL connections บน hosted database
- รันซ้ำ SQL ได้ด้วย `node scripts/test-comparison-access.mjs <path-to-@electric-sql/pglite>` ไม่มี dependency ใหม่ใน package.json
- API tests ครอบคลุม 401/402/503, ไม่เชื่อค่าจาก client, preview ไม่หักเครดิต, ฟรี 2–3 ชื่อ, การสลับลำดับชื่อ และการป้องกันซื้อรายงานเพื่อข้ามค่าบริการ
- ทดสอบ UI จากคอมโพเนนต์จริงด้วยบัญชี/เครดิตจำลอง: Login ก่อนเก็บ, คืนชื่อหลัง Login, แยกบัญชี A/B, เก็บข้ามหมวด, ส่งสี่ชื่อโดยไม่วิเคราะห์อัตโนมัติ, สามชื่อฟรีขณะออกจากระบบ, เครดิตไม่พอ, ยืนยัน/เปิดซ้ำ และคืนแบบฟอร์มหลัง Login โดยไม่ซื้ออัตโนมัติ
- ตรวจ build จริงเพิ่มเติม: กดหัวใจขณะไม่เข้าสู่ระบบไป `/login?redirect=%2Fnames`; เปรียบเทียบสองชื่อในหน้าเว็บได้โดยไม่เข้าสู่ระบบ; API 2/3 ชื่อตอบ 200 cost 0, 4/5 ชื่อที่ไม่เข้าสู่ระบบตอบ 401 และทุกคำตอบใช้ private/no-store; metadata ระบุ 2–3 ชื่อฟรีและมี H1 เดียว
- ผล fixture: ยอด 20 → 10 เครดิต มีการหักหนึ่งครั้งและสิทธิ์หนึ่งชุดหลังเปิดซ้ำหลายครั้ง; ห้าชื่อยังแสดงราคา 10 เครดิตต่อชุด ตรวจ modal บนมือถือ 390px

ไม่ได้ติดตั้ง migration บนฐาน hosted, ไม่ใช้เครดิตจริง, ไม่ Commit/Push และไม่เผยแพร่ production ในรอบนี้
