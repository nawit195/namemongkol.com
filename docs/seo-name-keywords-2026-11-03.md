# SEO: ตั้งชื่อมงคล วิเคราะห์ชื่อ และตั้งชื่อลูก

## เป้าหมายและข้อมูลตั้งต้น

เพิ่มผู้ใช้เครื่องมือฟรีจากการค้นหาภาษาไทยในประเทศไทย ก่อนเชื่อมไปบริการเสริมตามความต้องการ ไม่มีข้อมูล GSC พร้อมใช้ ณ วันที่จัดทำ จึงไม่ระบุ search volume, keyword difficulty, อันดับ หรือเป้าหมายเพิ่ม traffic เป็นตัวเลข

## หน้ารับคีย์เวิร์ด

| หน้า | คำหลัก / เจตนา | เส้นทางต่อ |
| --- | --- | --- |
| `/` | แบรนด์และภาพรวมเครื่องมือ | `/search`, `/name-check`, `/names` |
| `/search` | ตั้งชื่อมงคล, ค้นหาชื่อมงคล, ชื่อความหมายดี | เลือกชื่อ → `/name-check?name=...` |
| `/name-check` | วิเคราะห์ชื่อ, วิเคราะห์ชื่อ นามสกุล ฟรี | อ่านผล → ค้นหาหรือเปรียบเทียบตามความต้องการ |
| `/names` | ตั้งชื่อลูก, ตั้งชื่อลูกพร้อมความหมาย | หมวดชื่อ → เลือกชื่อ → วิเคราะห์กับนามสกุล |
| `/names/boys`, `/names/girls` | ตั้งชื่อลูกชาย / ตั้งชื่อลูกสาว | หมวดวันเกิดและเครื่องมือวิเคราะห์ |
| `/names/*/by-birthday/*` | ชื่อตามเพศและวันเกิด | รายชื่อเฉพาะกลุ่ม |
| `/name-analysis` | เปรียบเทียบและคัดกรองหลายชื่อ | เครื่องมือวิเคราะห์หลายชื่อเดิม |
| `/name-generator` | ตั้งชื่อด้วย AI | นำตัวเลือกไปตรวจชื่อเต็ม |
| `/premium-search` | คัดชื่อเฉพาะบุคคล / เปลี่ยนชื่อ Premium | บริการเสริมเดิม |

หน้าใหม่ใช้ข้อมูลสาธารณะจากระบบเดียวกับ /search คัดชื่อเพศละ 6 รายการเมื่อมีข้อมูลเพียงพอ รับความหมายที่ approved หรือใช้ความหมายจากชุด curated เดิมแทนข้อมูล legacy ที่ไม่มีสถานะ หากข้อมูลเดิมกำหนดเพศเป็น neutral ทั้งหมด ใช้หมวดเพศจากชุด curated ที่มีอยู่แล้วเฉพาะชื่อที่ไม่ซ้ำกันระหว่างสองหมวด ไม่ใช้คำแปล pending/draft/rejected และไม่เติมชื่อที่หายไปจากข้อมูลสาธารณะ หากรายการผ่านเกณฑ์ไม่ครบ แสดงเท่าที่มีและให้ schema นับตามจริง ไม่อนุมัติข้อมูลอัตโนมัติเพื่อให้ครบจำนวน คำอ่านต้อง approved เท่านั้น

## การวัดผลหลังเผยแพร่

1. ตรวจสถานะ index, canonical และ sitemap ของทั้งสามหน้าใน Search Console หลังเผยแพร่จริง
2. เก็บข้อมูล query + page (`query`, `page`, `clicks`, `impressions`, `ctr`, `position`) ให้ครบ 28 วันเป็นฐาน โดยใช้ Web Search / ประเทศไทย และเทียบเงื่อนไขเดิมทุกช่วง
3. ใช้ `npm run gsc:weekly:name-seo -- --input current.csv --compare previous.csv --output docs/reports/gsc-name-seo.md --period "YYYY-MM-DD to YYYY-MM-DD"` รายงานรองรับ /names และคำหลักทั้งสามแล้ว
4. เปรียบเทียบ 7 วันกับ 7 วันก่อนหน้า และ 28 วันกับ 28 วันก่อนหน้า ติดตาม impressions, clicks, CTR, average position, URL ที่ปรากฏต่อ query เดียวกัน และ Core Web Vitals จากข้อมูลผู้ใช้จริง
5. ตรวจ funnel เดิม `funnel.organic_landing`, `funnel.search.name_select`, `funnel.search.name_analyze` โดยแยก `page_path` ของหน้าใหม่ การกดวิเคราะห์เป็นขั้นเปิดเครื่องมือ ไม่ใช่ผลวิเคราะห์สำเร็จ การเลือกชื่อใน /names คือการกดวิเคราะห์โดยตรง ส่วน event name_select ยังคงใช้กับการเปิดดูชื่อใน /search ไม่เพิ่ม event ซ้ำ
6. ลิงก์ใหม่ใช้ data-track เป็นค่าคงที่ ไม่มีชื่อ นามสกุล หรือ query string ใน metadata; ไม่ส่งชื่อเป็น event label และไม่ผูกการเปลี่ยนแปลงอันดับกับงานรอบนี้โดยไม่มีหลักฐาน

ยังไม่ล็อก KPI traffic หรืออันดับจนกว่าจะมีฐานข้อมูลครบ การพัฒนารอบนี้ไม่รวมการ deploy, การย้าย URL, การแก้สูตรวิเคราะห์ หรือ backlink

## ผลตรวจในเครื่อง

- Production build ผ่าน ตรวจ HTML ที่สร้างจริงของหน้าแรก /names /search /name-check และ /name-generator: H1 หน้าเดียวละหนึ่งรายการ, แบรนด์ใน title ครั้งเดียว และ canonical ตรง URL
- FAQ ใน HTML ตรง JSON-LD ทุกข้อของ /names (5 ข้อ), /search (6 ข้อ) และ /name-check (7 ข้อ); /names มีตัวอย่างและลิงก์วิเคราะห์ครบ 12 ชื่อ จำนวน ItemList ตรงรายการจริง; sitemap มี /names และไม่มี URL ต้นทางที่ redirect
- Vitest: 48 ไฟล์ / 236 tests ผ่าน รวมกรณี legacy ที่จัดเพศเป็น neutral และความหมายที่ยังไม่อนุมัติ
- ESLint ทั้งโปรเจกต์: 0 errors, 46 warnings ในไฟล์เดิม; ไฟล์เนื้อหาและหน้าใหม่ที่ตรวจแยกไม่มี warning
- ตรวจเบราว์เซอร์ที่ความกว้าง 1280 และ 390 พิกเซล: หน้า /names แสดง 12 ชื่อ ไม่มี horizontal overflow, H1 เดียว และไม่พบ console error ในหน้าที่ทดสอบ
- ทดสอบหน้าแรก → /names → /name-check พร้อมชื่อที่เลือก โดยไม่เข้าสู่ระบบ; ล้างผลแล้ว URL กลับ /name-check และช่องชื่อกับนามสกุลว่าง
- ทดสอบกรอก “กานต์ ใจดี” ในแบบฟอร์มฟรี และตรวจว่าผลตัวอย่างอธิบายผลรวม 19 + 20 = 39 และคู่เลข 11, 15, 53, 39 ตรงกับฟังก์ชันจริง
- ทดสอบรายงาน GSC ด้วย CSV จำลอง: แยก cohort /names ได้ และแจ้ง query “ตั้งชื่อลูก” ที่ปรากฏทั้ง /names และ /search ได้
- ข้อมูลสถานะตรวจทานรุ่นใหม่ยังไม่ครบในฐานข้อมูลที่ใช้ทดสอบ หน้าใหม่ใช้ข้อมูล curated เดิมสำหรับ legacy โดยไม่แก้สถานะในฐานข้อมูล ไม่เผยแพร่คำอ่านรอตรวจ และไม่แปลงคำแปลร่างให้เป็น approved
