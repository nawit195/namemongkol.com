# Daily page traffic

The root `PageViewTracker` records pathname navigations, refreshes and restored back/forward-cache pages. Query/filter changes and React Strict Mode repeats do not create another view. Navigation identity is kept only in tab memory, separately from the redacted payload: opening two different meaning names records two views under `/meaning/:name`. A persistent random browser UUID distinguishes browsers across tabs; storage-disabled browsers fall back to an in-memory identity. This is a browser count, not verified people or accounts.

Only the pathname is retained: query strings, fragments and form values are excluded; UUID path segments are grouped as `:id`. Meaning detail URLs are grouped as `/meaning/:name` so names entered in the lookup form are not retained through the destination path. The `/meaning` hub and nickname meaning collections remain separate pages. Admin, API, auth callbacks and static assets are excluded. Local development, localhost, Vercel preview deployments, recognized crawler user agents, Do Not Track and Global Privacy Control are excluded. Client-only measurement can undercount blocked JavaScript and fast visits before hydration.

The server chooses the Asia/Bangkok date and derives a daily visitor HMAC using `PAGE_ANALYTICS_HASH_SECRET` (optional, server-only), falling back to `SUPABASE_SERVICE_ROLE_KEY`. No account ID, email or IP is stored. Keep the hashing key stable during each reporting day. A network/5xx retry reuses the event UUID; the database primary key prevents duplicate delivery from increasing views. The browser never retries 429 or other 4xx rejections. There is one write per navigation, at most one retry and no heartbeat/polling.

Before reading the request body or creating the database client, ingestion applies a bounded in-memory limiter: 120 requests per network per 60 seconds, a burst limit of 30 per 10 seconds, and a per-instance ceiling of 600 per 60 seconds. Network keys are HMACs retained only in a capped 2,048-entry map for 60 seconds; raw addresses are not stored or logged. Only deployments with `VERCEL=1` trust Vercel's overwritten `x-forwarded-for` header. Other environments share one fallback network bucket and ignore supplied `cf-connecting-ip`, `x-real-ip` and `x-forwarded-for`. Full maps reject new identities until expiry rather than evicting active limits. Rejections return 429 with Retry-After without reading the body or writing events. This is best-effort per instance, not a distributed security guarantee; multiple instances and restarts reset/separate limits, and high-volume legitimate traffic can be undercounted. See [Vercel request headers](https://vercel.com/docs/headers/request-headers#x-forwarded-for).

Declared request bodies over 2,048 bytes are rejected before reading. Undeclared/chunked bodies are read only up to 2,048 UTF-8 bytes, then canceled; malformed UTF-8/JSON is rejected. This limit is bytes, not JavaScript character count.

Apply both the original `daily_page_traffic` and follow-up `daily_page_traffic_permissions` migrations before deploying the application. The follow-up resets existing Supabase service-role default grants before allowing only SELECT/INSERT. `page_view_events` is service-only with RLS; neither guests nor members can read or write it directly, and the service role cannot UPDATE, DELETE or TRUNCATE events. The aggregate RPC is service-only. `/api/admin/page-traffic` verifies the user and database admin role before calling it. Responses are private/no-store. Reports are grouped in PostgreSQL, paginated at 50 rows and constrained to 31 calendar days, avoiding the Data API's row limit. No historical click events are backfilled as page views.

Open `/admin/page-traffic` or the “ผู้เข้าชมรายวัน” admin menu. Choose today, 7/30 days or custom dates, optionally filter a pathname, then submit. Each row shows one page on one Thai calendar day. The daily whole-site summary deduplicates a browser across pages. `visitorDays` across multiple dates sums daily unique browsers; it does not claim unique people across the entire period. Queries, including the daily summary, respect the path filter.

Validation: Vitest covers Thai midnight, sanitization, redacted-path navigation identity, 4xx versus network/5xx retries, opt-outs, limiter boundaries/resets/map caps, byte-limited streaming and API authorization. Run `node scripts/test-page-traffic.mjs path/to/@electric-sql/pglite` for both actual migrations: over 1000 views, cross-page daily deduplication, pagination, replay handling and database privileges under simulated Supabase default ALL grants.
