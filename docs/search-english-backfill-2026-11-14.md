# เพิ่มคำสะกดภาษาอังกฤษที่ขาดใน /search

## หลักการเผยแพร่

ผู้ใช้เลือกให้แสดงคำถอดเสียงแนะนำพร้อมป้าย “รอตรวจสอบ” การถอดเสียงไม่ใช่คำแปลหรือการยืนยันการสะกดในเอกสารของบุคคล หลักการอ้างอิง: [ราชบัณฑิตยสถาน หลักเกณฑ์การถอดอักษรไทยเป็นอักษรโรมันแบบถ่ายเสียง](https://www.arts.chula.ac.th/~ling/tts/ThaiRoman.pdf)

คง `english_name` เดิมทั้งหมด และแยกคำแนะนำไว้ใน `english_name_draft` พร้อมสถานะ ที่มา และคำอ่านที่ใช้สร้างคำสะกด เว็บรุ่นเดิมจึงยังไม่เผยคำแนะนำโดยขาดป้ายกำกับ เมื่อเผยแพร่โค้ดใหม่ รายการฉบับร่างจะแสดงทั้งตาราง มือถือ รายละเอียด API และ CSV

คำแนะนำจากคำอ่านที่เปลี่ยนไปจะถูกซ่อนไว้จนกว่าจะสร้างใหม่ ไม่เปลี่ยนสถานะคำอ่าน/ความหมาย ไม่คำนวณคะแนนหรือแก้สูตร และไม่เขียนตารางพรีเมียม

## ผลฐานจริง

- รายชื่อในฐานสาธารณะ 7,808 ชื่อ
- มีชื่ออังกฤษเดิม 1,002 ชื่อ: คงเดิมทั้งหมด
- เติมฉบับร่าง 6,616 ชื่อ: จากต้นทางพรีเมียมชื่อเดียวกัน 346 ชื่อ และถอดเสียงจากคำอ่านที่มีอยู่ 6,270 ชื่อ
- ทุกฉบับร่างมีสถานะ pending; ไม่ยกระดับเป็น approved อัตโนมัติ
- อีก 190 ชื่อยังไม่มีคำแนะนำ เพราะคำอ่านไม่สมบูรณ์หรือมีได้หลายเสียง เช่น พยัญชนะโดดและ ทร
- ชื่อเสริมในโค้ด 30 ชื่อมีคำแนะนำ pending ครบ ทำให้ชุด /search มีชื่ออังกฤษเดิมหรือคำแนะนำ 7,648 จาก 7,838 ชื่อ
- ตรวจหลังเขียน: ไม่มีอักขระผิดรูปในฉบับร่าง ไม่มีคำอ่านที่เปลี่ยนระหว่างทาง และไม่มีชื่อเพิ่ม/ลบ

รายการที่ต้องตรวจ: `outputs/english-name-needs-review-2026-11-14.csv` มีชื่อไทย คำอ่าน และเหตุผล ไม่รวม user data หรือรหัสแถวฐานข้อมูล

รอบนี้ยังไม่ Commit/Push หรือเผยแพร่โค้ด production การแสดงฉบับร่างบนเว็บไซต์จริงต้องเผยแพร่โค้ดใหม่ก่อน

ข้อจำกัดสภาพแวดล้อมในเครื่อง: Vercel CLI 65.16.0 ยืนยันว่า secret 11 ค่าเป็น Sensitive และดึงค่าจริงจาก production ไม่ได้ ไฟล์ .env.local ไม่มีค่า secret จริงแล้วและไม่มีค่าตัวแทน [SENSITIVE] ค้างอยู่ ต้องตั้งค่า local-only credentials ก่อนทดสอบการเชื่อมต่อจากเครื่อง การตรวจข้อมูลจริงรอบนี้ใช้ Supabase connector ส่วนการตรวจหน้าจอใช้ NameRow จริงกับข้อมูลจำลอง
